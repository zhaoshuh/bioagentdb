# Release note · v1.2-proteinopathies

- **Tag**: `v1.2-proteinopathies`
- **Date**: 2026-10-09 (R2 re-cut; same unpublished tag supersedes the R1 cut)
- **Changes vs v1.1**: **theme-membership relevance guard** (R1/R2 fix), applied at the source
  and to existing rows. A paper is linked to a disease theme only if it is disease-relevant
  (title hit, or ≥2 abstract mentions). Two origins were cleaned:
  1. `link` — "a theme's query matched" auto-links (6,025 removed in R1);
  2. `backfill` — home-theme membership written on DB init regardless of relevance
     (7,018 rows removed in R2; the guard is now built into `app/core/db.py` init and
     `scripts/backfill_themes.py` so restarts no longer re-add them).
  Papers and datasets are unchanged; only `paper_themes` rows were removed.
- **Release archive**: `data/releases/v1.2-proteinopathies.zip` · statistics:
  [`v1.2-stats/resource-stats.md`](v1.2-stats/resource-stats.md)

## Why v1.2
R1 (adversarial web review) found that the disease filter surfaced off-domain papers
(e.g. bone-marrow senescence, EEG-EMG decoding, a *Streptomyces* paper) because query hits and
home-theme backfill auto-linked themes. The relevance guard plus
`scripts/clean_memberships.py` fixes this; remaining borderline items were manually inspected
and are disease-relevant (e.g. subthalamic-nucleus/DBS, striatal cAMP). Regression: restarted
the service twice and confirmed memberships do not grow back (`_overlink_check2.py` shows no
off-domain members), and the live API totals match this release.
